# FID-007 — Eine Zahlenspalte ohne Zahlen

## Description

Amtliche Quellen unterdrücken kleine Fallzahlen aus Datenschutzgründen. Statt der Zahl steht dann ein Bereich, ein Vergleich oder ein Platzhalter: `1 bis 5`, `<5`, `NULL`, `k.A.`, `*`, die leere Zelle. Die Spalte heisst weiterhin «Anzahl», ihr Typ ist weiterhin «Zahl» — nur ein Teil der Zellen ist keine.

Drei Verhaltensweisen sind möglich, und sie sind **nicht** gleich schlimm:

| Verhalten | Bewertung |
|---|---|
| `int("1 bis 5")` wirft, der Aufruf bricht ab | **laut und schlecht** — der Nutzende sieht «unerwarteter interner Fehler» und weiss nichts |
| als `0` zählen | **still und schlimmer** — die Summe bleibt plausibel, ist zu tief, und durch nichts als falsch erkennbar |
| ausnehmen **und** kennzeichnen | **richtig** |

Der mittlere Fall ist der eigentliche Gegenstand dieses Checks. Ein Absturz ist ein Ärgernis mit Fehlermeldung; eine stille Null erzeugt eine Zahl, die niemand anzweifelt, weil ihr nichts anzusehen ist. Das Modell liest sie als Summe, die Nutzenden lesen sie als Summe, und sie ist eine Untergrenze, die sich als Summe ausgibt.

**Belegfall (`zh-education-mcp` / BISTA, 2026-08-03).** Die Quelle schreibt bei kleinen Fallzahlen `1 bis 5` statt einer Zahl. Gemessen: **18.6 %** der Sek-I-Zeilen und **18.1 %** der Staatsangehörigkeits-Zeilen. Kein Randfall — fast jede fünfte Zeile. `int()` warf, und der Aufrufer sah davon nur «unerwarteter interner Fehler».

**Warum das keine Ausnahmebehandlung ist, sondern Datentreue.** Wer die Zeile ausnimmt, ohne es zu sagen, liefert dieselbe zu tiefe Zahl wie der, der `0` zählt — nur ohne den Umweg. Die Kennzeichnung ist der Check, nicht das Ausnehmen: Erst sie macht aus einer falschen Summe eine richtige Untergrenze.

**Abgrenzung — dieser Check schliesst eine Lücke zwischen zweien.** `FID-003` behandelt die **Leermenge**: Es kam nichts, und das muss von Abwesenheit unterscheidbar sein. `DRIFT-002` behandelt den **Fallback**, der klammheimlich einen anderen Datensatz liefert. Hier kommt der **richtige** Datensatz, vollständig, und ein Fünftel seiner Zellen trägt keinen Wert, der sich addieren lässt. Die Zeile ist da, die Zahl fehlt, und niemand fragt danach.

**Abgrenzung zu `FID-006`.** Der prüft, ob das Feld **am erwarteten Ort** liegt. Hier liegt es dort und trägt etwas anderes, als sein Name verspricht — die Struktur ist in Ordnung, der Inhalt hat eine Klasse, die der Leser nicht kennt.

`high`: Die Wirkung ist eine Zahl, die falsch ist und richtig aussieht. Genau die Klasse, gegen die die `FID`-Kategorie steht.

## Verification

### Modus 1: code_review (wo aus einer Zelle eine Zahl wird)

```bash
# Jede Konvertierung auf einem Quellwert ist eine Behauptung über die Quelle.
grep -rnE '\b(int|float)\(\s*[a-z_]+(\.get\(|\[)' src/ --include=*.py

# Der stille Fall: ein Default, der aus einer Nicht-Zahl eine Null macht.
grep -rnE '\b(int|float)\(\s*[^)]*\bor\b\s*0|\.get\([^)]*,\s*0\s*\)' src/ --include=*.py

# Kennt der Code die Unterdrückungsmarker überhaupt?
grep -rniE '"1 bis 5"|"<5"|"k\.A\."|isdigit\(\)|suppress|unterdrueck|unterdrück' \
  src/ --include=*.py

# Und weist er sie aus?
grep -rniE 'suppressed|unterdrückt|nicht enthalten|Untergrenze' src/ --include=*.py
```

Ein `int(row["anzahl"])` ohne jede Kenntnis von Nicht-Zahlen ist der Befund. Ein `int(row.get("anzahl", 0))` ist der **schlimmere** Befund: Er wirft nicht einmal.

**Pass-Pattern** — die Nicht-Zahl wird zu `None`, nicht zu `0`:

```python
def _parse_count(value: object) -> int | None:
    """Zahl aus einem Zählwert, oder ``None``, wenn keine da ist.

    Die Quelle unterdrückt kleine Fallzahlen und schreibt statt einer Zahl
    einen Bereich (``1 bis 5``), dazu ``NULL`` und die leere Zelle. Am
    2026-08-03 waren das 18.6 % beziehungsweise 18.1 % der Zeilen.

    Sie als 0 zu zählen wäre schlimmer als ein Absturz: Die Summe wäre
    plausibel, still zu tief und durch nichts als falsch erkennbar. Deshalb
    ``None`` — der Aufrufer entscheidet, und die Tools weisen die Zahl der
    unterdrückten Zeilen aus, statt sie verschwinden zu lassen.
    """
    raw = str(value if value is not None else "").strip()
    return int(raw) if raw.isdigit() else None
```

Und die Kennzeichnung, ohne die das Ausnehmen nur eine leisere Lüge wäre:

```python
def _suppression_note(suppressed: int, total: int) -> str | None:
    """Hinweiszeile auf unterdrückte Werte, oder ``None``, wenn es keine gibt.

    Eine Summe, aus der ein Fünftel der Zeilen stillschweigend fehlt, ist
    keine Summe — sie ist eine Untergrenze, die sich als Summe ausgibt.
    """
    if suppressed <= 0:
        return None
    return (
        f"**Hinweis:** {suppressed} von {total} Zeilen enthalten keinen "
        f"Zahlenwert (die Quelle schreibt bei kleinen Fallzahlen «1 bis 5» "
        f"statt einer Zahl). Sie sind in den Summen **nicht** enthalten; "
        f"die echten Werte liegen entsprechend höher."
    )
```

**Fail-Pattern 1** — laut und schlecht:

```python
total = sum(int(r["anzahl"]) for r in rows)      # ValueError bei «1 bis 5»
```

**Fail-Pattern 2** — still und schlimmer:

```python
total = sum(int(r.get("anzahl") or 0) for r in rows)   # 18 % der Zeilen zählen als 0
```

### Modus 2: runtime_test (die Marker der Quelle, mit Gegenprobe)

```python
@pytest.mark.parametrize("marker", ["1 bis 5", "<5", "NULL", "k.A.", "", "*"])
def test_a_suppressed_cell_is_not_a_zero(marker):
    assert _parse_count(marker) is None, f"{marker!r} wurde zu einer Zahl"


def test_the_note_appears_and_names_both_numbers():
    rows = [{"anzahl": "7"}, {"anzahl": "1 bis 5"}, {"anzahl": "3"}]
    total, suppressed = _sum_counts(rows)
    assert total == 10
    assert suppressed == 1
    note = _suppression_note(suppressed, len(rows))
    assert note and "1 von 3" in note


def test_counting_them_as_zero_would_be_caught():
    """Gegenprobe: die stille Variante nachstellen und zeigen, dass sie auffällt."""
    rows = [{"anzahl": "7"}, {"anzahl": "1 bis 5"}, {"anzahl": "3"}]
    silent = sum(int(r["anzahl"]) if r["anzahl"].isdigit() else 0 for r in rows)
    total, suppressed = _sum_counts(rows)
    assert silent == total, "gleiche Summe — der Unterschied ist der Hinweis"
    assert suppressed > 0, "und ohne ihn ist die Summe von einer echten nicht zu trennen"
```

Der letzte Test ist der Kern: Die stille Null und das korrekte Ausnehmen liefern **dieselbe Zahl**. Was sie unterscheidet, ist ausschliesslich die Kennzeichnung. Wer das einmal ausgeführt hat, baut den Hinweis nicht mehr weg.

### Modus 3: runtime_test (gegen die echte Antwort)

Welche Marker eine Quelle benutzt, weiss nur die Quelle. Ein Mock, der `1 bis 5` kennt, weil der Autor ihn so geschrieben hat, belegt nicht, dass die Quelle nicht auch `<5` schreibt.

```python
@pytest.mark.live
async def test_every_non_numeric_marker_the_source_uses_is_known():

    unknown = {
        r["anzahl"] for r in rows
        if not str(r["anzahl"]).strip().isdigit() and str(r["anzahl"]).strip()
    } - KNOWN_SUPPRESSION_MARKERS
    assert not unknown, f"unbekannte Marker in der Zählspalte: {sorted(unknown)}"
```

## Pass Criteria

- [ ] Jede Konvertierung eines Quellwerts in eine Zahl kennt den Fall «keine Zahl» und behandelt ihn ausdrücklich
- [ ] Eine unterdrückte Zelle wird **nicht** zu `0` — weder durch `or 0` noch durch einen `.get(…, 0)`-Default noch durch ein stillschweigendes `except`
- [ ] Eine unterdrückte Zelle bricht den Aufruf **nicht** ab; sie wird ausgenommen
- [ ] Das Tool-Result **nennt** die Zahl der ausgenommenen Zeilen — ohne sie ist die Summe von einer vollständigen nicht zu unterscheiden
- [ ] Der Hinweis sagt, in welche Richtung die Summe abweicht («die echten Werte liegen höher»), nicht nur, dass etwas fehlt
- [ ] Die bekannten Marker der Quelle sind an einer Stelle benannt, nicht über die Lesestellen verstreut
- [ ] Ein Live-Test hält die tatsächlich vorkommenden Nicht-Zahlen gegen diese Liste — welche Marker eine Quelle benutzt, weiss nur die Quelle
- [ ] **Gegenprobe:** Die stille Variante ist einmal danebengestellt worden und liefert dieselbe Zahl. Wer das nicht gezeigt hat, hält den Hinweis für Kosmetik

## Common Failures

| Anti-Pattern | Risiko |
|---|---|
| `int(row["anzahl"])` ohne Kenntnis von Nicht-Zahlen | Absturz mit «unerwarteter interner Fehler»; der Nutzende erfährt nichts |
| `int(row.get("anzahl") or 0)` | 18 % der Zeilen zählen als 0; die Summe bleibt plausibel und ist zu tief |
| `try: … except ValueError: continue` | Richtiges Ausnehmen, fehlende Kennzeichnung — dieselbe falsche Zahl, leiser |
| Hinweis nur im README | Das Modell liest das Tool-Result, nicht das README (`FID-005`) |
| Hinweis nennt keine Richtung | «Werte fehlen» lässt offen, ob die Summe zu hoch oder zu tief ist |
| Marker-Liste über die Lesestellen verstreut | Die Stelle, die `<5` nicht kennt, ist genau die, die niemand testet |
| Marker-Liste nur gegen ein Fixture geprüft | Der Mock kennt die Marker, die der Autor kannte |
| Unterdrückte Zeile als Leermenge behandelt | Falscher Kanal: `FID-003` ist «es kam nichts», hier kam die Zeile |

## Remediation

```diff
+ KNOWN_SUPPRESSION_MARKERS = frozenset({"1 bis 5", "<5", "NULL", "k.A.", "*", ""})
+
+
+ def _parse_count(value: object) -> int | None:
+     """Zahl aus einem Zählwert, oder ``None``, wenn keine da ist."""
+     raw = str(value if value is not None else "").strip()
+     return int(raw) if raw.isdigit() else None
+
+
+ def _sum_counts(rows: list[dict], field: str = "anzahl") -> tuple[int, int]:
+     """Summe und Anzahl der ausgenommenen Zeilen — beide, immer."""
+     values = [_parse_count(r.get(field)) for r in rows]
+     return sum(v for v in values if v is not None), sum(v is None for v in values)
+
+
- total = sum(int(r.get("anzahl") or 0) for r in rows)
- return f"Total: {total}"
+ total, suppressed = _sum_counts(rows)
+ note = _suppression_note(suppressed, len(rows))
+ return f"Total: {total}" + (f"\n\n> {note}" if note else "")
```
