# SEC-024 — Eingehende Host-Allow-List bei 0.0.0.0-Bind

## Description

`SEC-016` verlangt, dass `0.0.0.0` nicht als Code-Default steht, und erlaubt es für Container. Damit ist die Frage «wer darf mich erreichen» aber nicht beantwortet, sondern nur verschoben: Wer an alle Interfaces bindet, kann sie nicht mehr über das Interface stellen. Sie muss dann an der eingehenden Anfrage gestellt werden — **unter welchem Hostnamen darf der Server angesprochen werden.**

Ohne diese Prüfung ist der Server offen für **eingehendes DNS-Rebinding**: Eine beliebige Webseite, die das Opfer im Browser öffnet, lässt `attacker.com` auf `127.0.0.1` (oder die LAN-IP des Servers) auflösen und spricht den MCP-Server dann aus dem Browser des Opfers an. Die Same-Origin-Policy hilft nicht — für den Browser ist es dieselbe Herkunft. Der Angreifer erbt damit alles, was der Server kann: Tool-Inventar, Filesystem-Zugriffe, hinterlegte API-Keys.

Das ist die **eingehende** Hälfte von `Sec 4.4`. `SEC-004` und `SEC-005` decken die ausgehende ab — dort ist der Server der Angreifer wider Willen, hier das Ziel.

### Die zwei Fehlermodi sind nicht gleich sichtbar

Das Python-SDK (`mcp` 2.x) bringt den Schutz mit, aber seine Vorbelegung hängt am `host`-Wert, den `sse_app()` bzw. `streamable_http_app()` bekommen:

| `host` an den App-Builder | `transport_security` | Ergebnis |
|---|---|---|
| nicht durchgereicht → Default `127.0.0.1` | `None` | Schutz **an**, Allow-List `127.0.0.1:*`, `localhost:*`, `[::1]:*` → jede Anfrage unter echtem Hostnamen bekommt `HTTP 421` |
| `0.0.0.0` durchgereicht | `None` | Schutz **aus** — der Server nimmt **jeden** `Host`-Header an |
| beliebig | explizit gesetzt | gilt, was dort steht |

Der Auto-Zweig greift ausschliesslich, wenn `host` in `("127.0.0.1", "localhost", "::1")` liegt. Für jeden anderen Wert bleibt `transport_security` bei `None` — und die Middleware ist dann per Konstruktor auf `enable_dns_rebinding_protection=False` vorbelegt, ausdrücklich «for backwards compatibility».

**Damit ist die gefährliche Konfiguration die unauffällige.** Wer `0.0.0.0` korrekt durchreicht, bekommt einen Server, der startet, antwortet, Health-Checks besteht — und jeden Host-Header akzeptiert. Wer es vergisst, bekommt `HTTP 421` und merkt es in der ersten Minute. Der laute Fall ist der sichere; der stille ist der Befund. Das ist dieselbe Asymmetrie, die `OPS-005` für Pipelines beschreibt: Was nicht läuft, sieht aus wie was bestanden hat.

Ein Deployment hinter einem Ingress, das nur einen Hostnamen durchlässt, entschärft das — aber es macht die Prüfung nicht überflüssig, sondern verlagert sie auf eine Ebene, die belegt werden muss. Zwei Schichten, die beide «der andere macht das» annehmen, sind keine.

## Verification

### Modus 1: code_review (wird `host` durchgereicht, wird die Liste gesetzt?)

```bash
# Wird eine eigene App gebaut — oder läuft alles über run()?
grep -rnE "sse_app\(|streamable_http_app\(|http_app\(" src/

# Wird die Security explizit konfiguriert?
grep -rnE "TransportSecuritySettings|allowed_hosts|allowed_origins|enable_dns_rebinding" src/

# Woher kommt der Hostname — Env oder hartkodiert?
grep -rnE "MCP_ALLOWED_HOSTS|ALLOWED_HOSTS|PUBLIC_HOST|EXTERNAL_HOST" src/
```

**Pass-Pattern — Allow-List aus dem Deployment, Bind-Adresse getrennt davon:**

```python
import os
from mcp.server.mcpserver import MCPServer
from mcp.server.transport_security import TransportSecuritySettings

mcp = MCPServer("zurich-opendata")

# Bind-Adresse: wo lauscht der Prozess.
host = os.environ.get("MCP_HOST", "127.0.0.1")
port = int(os.environ.get("MCP_PORT", "8000"))

# Allow-List: unter welchen Namen er angesprochen werden darf.
# Zwei verschiedene Fragen, zwei verschiedene Variablen.
allowed = [h.strip() for h in os.environ.get("MCP_ALLOWED_HOSTS", "").split(",") if h.strip()]

if host not in ("127.0.0.1", "localhost", "::1") and not allowed:
    raise SystemExit(
        "MCP_HOST bindet an alle Interfaces, aber MCP_ALLOWED_HOSTS ist leer. "
        "Ohne Allow-List nimmt der Server jeden Host-Header an."
    )

security = TransportSecuritySettings(
    enable_dns_rebinding_protection=True,
    allowed_hosts=allowed or ["127.0.0.1:*", "localhost:*", "[::1]:*"],
    allowed_origins=[f"https://{h.split(':')[0]}" for h in allowed],
)

app = mcp.streamable_http_app(transport_security=security, host=host)
```

Der Abbruch ist der Kern des Musters: Er verwandelt die stille Fehlkonfiguration in eine laute. Ein `0.0.0.0`-Bind ohne Allow-List startet dann gar nicht mehr, statt offen zu laufen.

**Fail-Pattern 1 — der stille, gefährliche Fall:**

```python
# FAIL: host korrekt durchgereicht, Security nicht gesetzt.
# transport_security bleibt None, der Auto-Zweig greift bei 0.0.0.0 nicht,
# die Middleware ist auf enable_dns_rebinding_protection=False vorbelegt.
app = mcp.streamable_http_app(host="0.0.0.0")
# Server läuft, Health-Check grün, akzeptiert jeden Host-Header.
```

**Fail-Pattern 2 — der laute Fall (kein Sicherheits-, ein Verfügbarkeitsproblem):**

```python
# FAIL: host nicht durchgereicht. Default 127.0.0.1 aktiviert den Schutz
# mit der Localhost-Allow-List — auf einem 0.0.0.0-Deployment lehnt der
# Server damit jede Anfrage unter dem echten Namen mit HTTP 421 ab.
app = mcp.streamable_http_app()
uvicorn.run(app, host="0.0.0.0", port=8000)
```

**Fail-Pattern 3 — Allow-List im Code geraten:**

```python
# FAIL: Der von aussen erreichbare Name hängt an Domain, Ingress und Umgebung.
# Im Prozess ist er prinzipiell unbekannt. Eine hartkodierte Liste ist geraten
# und erzeugt in der ersten fremden Umgebung genau das HTTP 421.
allowed_hosts=["mcp.example.com"]
```

Zur Abgrenzung: `SEC-021` führt «Allow-List aus Env-Var» als Fail-Pattern — das gilt für **Egress**, wohin der Server sprechen darf. Hier ist die Umgebungs-Konfiguration die geforderte Form. Beide Variablen heissen in der Praxis `ALLOWED_HOSTS`; vor dem Anlegen eines Findings die Richtung klären.

### Modus 2: runtime_test (fremder Host-Header wird abgelehnt)

```bash
BASE=http://127.0.0.1:8000/mcp
BODY='{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
HDR='-H Content-Type:application/json -H Accept:application/json,text/event-stream'

# 1. Erlaubter Name — muss durchgehen
curl -s -o /dev/null -w "erlaubt:      %{http_code}\n" -X POST $HDR \
  -H "Host: mcp.example.com" -d "$BODY" "$BASE"

# 2. Fremder Name — muss 421 bekommen
curl -s -o /dev/null -w "fremd:        %{http_code}\n" -X POST $HDR \
  -H "Host: evil.attacker.com" -d "$BODY" "$BASE"

# 3. Fremde Origin — muss 403 bekommen
curl -s -o /dev/null -w "fremd-origin: %{http_code}\n" -X POST $HDR \
  -H "Host: mcp.example.com" -H "Origin: https://evil.attacker.com" -d "$BODY" "$BASE"
```

**Pass:** `200` / `421` / `403`. **Fail:** dreimal `200` — dann ist der Schutz aus, unabhängig davon, was in der Config zu stehen scheint.

Der zweite Aufruf ist die eigentliche Gegenprobe. Ein Test, der nur den erlaubten Namen prüft, bestätigt lediglich, dass der Server läuft — er kann einen abgeschalteten Schutz nicht von einem funktionierenden unterscheiden.

### Modus 3: config_check (der Name steht im Deployment)

```bash
grep -rnE "MCP_ALLOWED_HOSTS|ALLOWED_HOSTS" railway.toml render.yaml k8s/ helm/ \
  docker-compose*.yml .env.example 2>/dev/null
```

**Pass:** Der öffentliche Hostname ist dort gesetzt, wo er bekannt ist — im Deployment-Manifest — und `.env.example` dokumentiert die Variable, damit ein neues Deployment sie nicht übersieht.

## Pass Criteria

- [ ] Bei einem Bind ausserhalb von Localhost ist `TransportSecuritySettings` **explizit** gesetzt — nicht dem Auto-Verhalten überlassen
- [ ] `enable_dns_rebinding_protection=True` steht explizit da
- [ ] `allowed_hosts` stammt aus der Deployment-Konfiguration, nicht aus dem Code
- [ ] Der Start bricht ab, wenn ausserhalb von Localhost gebunden wird und die Allow-List leer ist
- [ ] Der konfigurierte `host` wird an `sse_app()` / `streamable_http_app()` durchgereicht — nicht nur an den ASGI-Server
- [ ] `allowed_origins` ist gesetzt, wenn Browser-Clients vorkommen
- [ ] Ein Runtime-Test belegt beide Richtungen: erlaubter Host `200`, fremder Host `421`
- [ ] Steht ein Ingress davor, der Hostnamen filtert, ist diese Regel benannt — nicht angenommen

## Common Failures

| Anti-Pattern | Konsequenz |
|---|---|
| `streamable_http_app(host="0.0.0.0")` ohne `transport_security` | Schutz still aus, jeder `Host`-Header wird akzeptiert |
| `host` nur an `uvicorn.run()`, nicht an den App-Builder | Default `127.0.0.1` → Localhost-Allow-List → `HTTP 421` für alle |
| `allowed_hosts` im Code hartkodiert | In der ersten fremden Umgebung falsch — geraten, nicht gewusst |
| Allow-List gesetzt, aber `enable_dns_rebinding_protection` nicht | Die Liste wird nicht ausgewertet |
| Nur der erlaubte Host getestet | Ein abgeschalteter Schutz besteht diesen Test |
| «Der Ingress filtert das schon» ohne Beleg | Zwei Schichten, die beide auf die andere zeigen |
| `allowed_hosts=["*"]` als Abkürzung | Kein Wildcard für den Namensteil — der Eintrag matcht wörtlich `*` und lehnt alles ab |

## Remediation

1. Klären, ob der Server überhaupt eine eigene App baut. Wer `mcp.run(transport=..., host=..., port=...)` benutzt, reicht den `host` bereits korrekt durch — `run()` gibt ihn an den App-Builder weiter. Der `421`-Fall entfällt damit, der stille aber **nicht**: Auch hier bleibt `transport_security` bei `None` und der Auto-Zweig greift bei `0.0.0.0` nicht. `run()` nimmt das Settings-Objekt selbst entgegen, das ist der kürzeste Fix:

   ```python
   mcp.run(transport="streamable-http", host=host, port=port, transport_security=security)
   ```
2. `host` an `sse_app()` / `streamable_http_app()` durchreichen, nicht nur an den ASGI-Server.
3. `TransportSecuritySettings` explizit setzen, sobald ausserhalb von Localhost gebunden wird. Auf das Auto-Verhalten zu bauen heisst, sich auf einen Zweig zu verlassen, der bei `0.0.0.0` gar nicht greift.
4. Die Allow-List aus dem Environment lesen und im Deployment-Manifest setzen. `.env.example` mitpflegen.
5. Den Start abbrechen lassen, wenn ausserhalb von Localhost gebunden wird und die Liste leer ist.
6. Den `421`-Fall einmal wirklich auslösen — mit `curl -H "Host: evil.attacker.com"`. Ein Schutz, der nie abgelehnt hat, ist unbelegt.

```diff
- app = mcp.streamable_http_app(host="0.0.0.0")
+ security = TransportSecuritySettings(
+     enable_dns_rebinding_protection=True,
+     allowed_hosts=os.environ["MCP_ALLOWED_HOSTS"].split(","),
+ )
+ app = mcp.streamable_http_app(transport_security=security, host="0.0.0.0")
```

Zur Syntax der Liste: Einträge matchen den `Host`-Header wörtlich, inklusive Port. `example.com:*` ist die einzige Wildcard-Form und deckt beliebige Ports ab — für den Namensteil gibt es keine. Ein Server hinter `https://mcp.example.com` (Port 443, im Header meist weggelassen) braucht `mcp.example.com`; wer unsicher ist, nimmt `mcp.example.com` und `mcp.example.com:*`.
