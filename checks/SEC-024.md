# SEC-024 — Inbound Host/Origin-Allow-List

## Description

Der Angriff ist DNS-Rebinding, aber die **eingehende** Variante: Eine Seite im Netz des Betreibers löst ihren eigenen Hostnamen auf die Adresse dieses MCP-Servers auf und spricht dann aus dem Browser mit ihm. Der Angreifer braucht keinen Netzzugang — er braucht nur, dass jemand im richtigen Netz seine Seite öffnet. Was er erbt, ist alles, was der Server kann: Tool-Inventar, Filesystem-Zugriffe, hinterlegte Credentials.

`SEC-005` beschreibt den gleichnamigen Angriff in der **ausgehenden** Richtung — dort löst der Server einen Angreifer-Hostnamen auf und wird zum Werkzeug. Hier ist er das Ziel. Zwei verschiedene Angriffe unter einem Namen; siehe dort die Abgrenzung.

### Warum die naheliegenden Kontrollen nicht greifen

Drei Antworten liegen nahe, und alle drei gehen an dieser Frage vorbei:

| Kontrolle | Warum sie hier nicht hilft |
|---|---|
| **CORS** | Aus Browsersicht ist die Anfrage **same-origin**. Der Hostname der angreifenden Seite zeigt auf diesen Server; es gibt keinen Cross-Origin-Request, den eine CORS-Policy prüfen könnte. |
| **Auth-Token** | Das Token sagt, **wer** fragt. Die angreifende Seite läuft in einem Kontext, der bereits eines hält — im Browser eines Mitarbeiters, in dessen Netz. Ein gültiges `Bearer` rettet einen fremden Host nicht. |
| **Egress-Allow-List (`SEC-021`)** | Die entscheidet, **wohin** der Server sprechen darf. Das ist die Gegenrichtung und beantwortet die Frage gar nicht. |

Nur die `Host`-Prüfung beantwortet sie: **unter welchem Namen darf dieser Server angesprochen werden.**

### Die Kontrolle ist per Default fail-open

Das Python-SDK (`mcp` 2.x) bringt den Schutz mit, aber seine Vorbelegung hängt am `host`-Wert, den der App-Builder bekommt. Der Auto-Zweig greift ausschliesslich, wenn `host` in `("127.0.0.1", "localhost", "::1")` liegt — dann schaltet er `enable_dns_rebinding_protection=True` mit einer Localhost-Allow-List scharf. Für jeden anderen Wert bleibt `transport_security` bei `None`, und `TransportSecurityMiddleware` belegt dann ausdrücklich «for backwards compatibility» mit `enable_dns_rebinding_protection=False` vor.

**Damit ist ausgerechnet das korrekt konfigurierte Cloud-Deployment ungeschützt.** Wer `0.0.0.0` sauber an den App-Builder durchreicht, bekommt einen Server, der startet, antwortet, Health-Checks besteht — und jeden `Host`-Header annimmt. Wer den Wert vergisst, bekommt die Localhost-Liste und damit `HTTP 421` für jeden echten Namen, also einen Fehler in der ersten Minute. Der laute Fall ist der harmlose.

Das ist auch der Grund für `high` statt `critical`: `SEC-016` trägt `critical` für die Netzwerk-Exposition selbst und macht für Container eine Ausnahme; dieser Check ist die kompensierende Kontrolle für genau diese Ausnahme. Er ist wichtig, aber er ist eine Verteidigungsschicht, keine Exposition.

## Verification

### Modus 1: code_review (Evidence 1 — die Verdrahtung)

```bash
# Wo wird die App gebaut, und über welche Pfade?
grep -rnE "sse_app\(|streamable_http_app\(|build_http_app|create_http_app|mcp\.run\(" src/

# Wird die Security überhaupt verdrahtet?
grep -rnE "TransportSecuritySettings|transport_security|allowed_hosts|allowed_origins" src/

# Woher kommt die Liste?
grep -rnE "MCP_ALLOWED_HOSTS|MCP_ALLOWED_ORIGINS|MCP_CORS_ORIGINS" src/ .env.example
```

**Pass-Pattern:**

```python
import logging
import os
from mcp.server.transport_security import TransportSecuritySettings

LOOPBACK = ("127.0.0.1", "localhost", "::1")


def build_transport_security(host: str, port: int) -> TransportSecuritySettings | None:
    """Host/Origin-Allow-List für den eingehenden Transport.

    Portgenau: Einträge werden wörtlich gegen den `Host`-Header verglichen,
    ein Eintrag trägt also seinen Port.
    """
    configured = [h.strip() for h in os.environ.get("MCP_ALLOWED_HOSTS", "").split(",") if h.strip()]

    if not configured:
        if host not in LOOPBACK:
            logging.warning(
                "MCP_ALLOWED_HOSTS ist nicht gesetzt und der Bind (%s) ist kein Loopback — "
                "die eingehende Host-Prüfung bleibt AUS. Setze MCP_ALLOWED_HOSTS auf die "
                "Namen, unter denen dieser Server erreichbar ist (mit Port).",
                host,
            )
            return None
        configured = []

    # Loopback bleibt immer drin: Container-Health-Checks sprechen den Server
    # unter 127.0.0.1 an und würden sonst von der eigenen Allow-List abgewiesen.
    allowed_hosts = sorted({*configured, *(f"{h}:{port}" for h in LOOPBACK)})

    # Konfigurierte CORS-Origins mit aufnehmen. Ohne das weist der Transport
    # genau die Browser-Clients ab, für die CORS geöffnet wurde — die Öffnung
    # wäre wirkungslos und der Fehler schwer zu finden.
    # `*` wird NICHT übernommen: Origins werden literal verglichen, der Eintrag
    # würde also auf die Zeichenkette "*" matchen und sonst nichts.
    cors = [o.strip() for o in os.environ.get("MCP_CORS_ORIGINS", "").split(",") if o.strip()]
    allowed_origins = sorted({o for o in cors if o != "*"} | {f"http://{h}:{port}" for h in LOOPBACK})

    return TransportSecuritySettings(
        enable_dns_rebinding_protection=True,
        allowed_hosts=allowed_hosts,
        allowed_origins=allowed_origins,
    )
```

Vier Eigenschaften, auf die beim Review zu achten ist:

1. **Portgenau.** Einträge werden wörtlich verglichen. `mcp.example.com` und `mcp.example.com:8443` sind zwei verschiedene Einträge. Die einzige Wildcard-Form ist der Port-Suffix `name:*`; für den Namensteil gibt es keine.
2. **Loopback bleibt drin.** Sonst weist der Server den Health-Check seines eigenen Containers ab, und das Deployment stirbt an der Kontrolle statt am Angriff.
3. **CORS-Origins wandern in die Origin-Liste des Transports.** Zwei Schichten, die dieselbe Frage verschieden beantworten, sind eine Fehlkonfiguration mit Ansage.
4. **`*` wird nicht übernommen.** Ein Wildcard, das nur sich selbst matcht, ist schlimmer als kein Eintrag — es sieht nach Öffnung aus und wirkt wie eine Sperre.

**Fail-Pattern:**

```python
# FAIL: Liste im Code geraten. Auf 0.0.0.0 ist der von aussen erreichbare
# Name im Prozess unbekannt — er hängt an Domain, Ingress und Umgebung.
allowed_hosts=["mcp.example.com"]

# FAIL: Port fällt auf dem Weg zum App-Builder weg. Die Loopback-Einträge
# nennen dann einen Port, den niemand bedient.
app = build_http_app(host=host)          # port defaultet intern

# FAIL: `*` aus der CORS-Konfiguration durchgereicht.
allowed_origins = cors_origins           # enthält "*"
```

### Modus 2: runtime_test (Evidence 2 — richtiger Hostname, falscher Port)

```bash
BASE=http://127.0.0.1:8000/mcp
BODY='{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
H='-H Content-Type:application/json -H Accept:application/json,text/event-stream'

# 1. Erlaubter Eintrag, exakt wie konfiguriert
curl -s -o /dev/null -w "exakt:        %{http_code}\n" -X POST $H \
  -H "Host: mcp.example.com:8443" -d "$BODY" "$BASE"

# 2. TRAGEND: derselbe Name, anderer Port
curl -s -o /dev/null -w "falscher Port: %{http_code}\n" -X POST $H \
  -H "Host: mcp.example.com:9999" -d "$BODY" "$BASE"

# 3. Auth rettet einen fremden Host nicht
curl -s -o /dev/null -w "mit Token:    %{http_code}\n" -X POST $H \
  -H "Authorization: Bearer $MCP_AUTH_TOKEN" \
  -H "Host: evil.example.com" -d "$BODY" "$BASE"
```

**Pass:** `200` / `421` / `421`.

**Der zweite Aufruf ist der einzige, der etwas beweist.** Ein Test gegen `evil.example.com` allein zeigt nichts: Wäre die Allow-List gar nicht verdrahtet und das SDK auf seine Localhost-Policy zurückgefallen, würde dieselbe Anfrage ebenfalls mit `421` abgewiesen — aus einem völlig anderen Grund. Der Test bestünde, und die Kontrolle wäre trotzdem nicht da.

`mcp.example.com:9999` schliesst das aus. Der Name steht auf der konfigurierten Liste, der Port nicht. Nur eine **tatsächlich übergebene, portgenaue** Liste kann diesen Fall abweisen. Der Test scheitert damit aus seinem eigenen Grund, nicht aus dem eines Defaults.

Derselbe Gedanke gilt für die Gegenrichtung: Ein Positiv-Test, der `MCP_ALLOWED_HOSTS` selbst setzt, kann die Verdrahtung des `host`-Kwargs nicht prüfen — bei expliziter Allow-List ist der Kwarg irrelevant. Tragend wird er erst, wenn das SDK raten muss.

### Modus 3: config_check (der Name steht im Deployment)

```bash
grep -rnE "MCP_ALLOWED_HOSTS|MCP_CORS_ORIGINS" railway.toml render.yaml k8s/ helm/ \
  docker-compose*.yml .env.example 2>/dev/null
```

**Pass:** Der öffentliche Hostname steht dort, wo er bekannt ist — im Deployment-Manifest — und `.env.example` dokumentiert die Variable, damit ein neues Deployment sie nicht übersieht.

## Pass Criteria

- [ ] **Evidence 1:** `TransportSecuritySettings` ist im Code an den Transport verdrahtet, mit `enable_dns_rebinding_protection=True`
- [ ] Die Allow-List stammt aus der Deployment-Konfiguration (`MCP_ALLOWED_HOSTS`), nicht aus dem Code
- [ ] Einträge sind portgenau — ein Eintrag trägt seinen Port
- [ ] Loopback ist immer enthalten, mit dem tatsächlich bedienten Port
- [ ] Konfigurierte CORS-Origins sind in der Origin-Liste des Transports enthalten
- [ ] `*` wird aus der CORS-Konfiguration **nicht** übernommen
- [ ] Fehlt die Variable auf einem Nicht-Loopback-Bind, bleibt der Schutz aus **und eine Startwarnung sagt es**
- [ ] **Evidence 2:** Ein Test weist «richtiger Hostname, falscher Port» ab — nicht nur einen fremden Namen
- [ ] Ein Test belegt, dass ein gültiges Auth-Token einen fremden Host nicht rettet
- [ ] Die Allow-List erreicht **jeden** Netzpfad, über den der Server bedient werden kann

## Common Failures

| Anti-Pattern | Konsequenz |
|---|---|
| Kein `transport_security` bei Nicht-Loopback-Bind | Schutz still aus; jeder `Host`-Header wird angenommen |
| Allow-List im Code hartkodiert | Auf `0.0.0.0` geraten — weist genau das Deployment ab, das sie schützen soll |
| Einträge ohne Port | Wörtlicher Vergleich schlägt fehl, sobald ein Port im Header steht |
| Loopback nicht in der Liste | Container-Health-Check bekommt `421`, Deployment gilt als kaputt |
| Loopback mit falschem Port | Gleiche Wirkung, schwerer zu sehen |
| CORS-Origins nicht in der Origin-Liste | Der Transport weist genau die Browser-Clients ab, für die CORS geöffnet wurde |
| `*` aus CORS übernommen | Matcht literal `*` und sonst nichts — sieht nach Öffnung aus, wirkt als Sperre |
| Nur gegen `evil.example.com` getestet | Eine zurückgefallene Loopback-Policy besteht diesen Test ebenfalls |
| Positiv-Test setzt die Variable selbst | Kann die `host`-Verdrahtung nicht prüfen — bei expliziter Liste ist der Kwarg irrelevant |
| Liste nur auf einem von mehreren App-Pfaden | Der Schutz hängt still davon ab, welcher Zweig zufällig greift |

## Remediation

1. Alle Netzpfade auflisten, über die der Server bedient werden kann, und die Allow-List auf **jedem** verdrahten.
2. `TransportSecuritySettings` explizit setzen, sobald ausserhalb von Loopback gebunden wird — nicht auf das Auto-Verhalten des SDK bauen, das bei `0.0.0.0` gar nicht greift.
3. Liste aus dem Environment lesen, portgenau, Loopback ergänzen, CORS-Origins aufnehmen, `*` verwerfen.
4. Startwarnung ergänzen, wenn die Variable fehlt und der Bind kein Loopback ist.
5. Den Test «richtiger Hostname, falscher Port» schreiben — und ihn per Mutation gegenprüfen: `transport_security` aus dem App-Builder entfernen, dann muss er scheitern. Tut er es nicht, prüft er den Default, nicht die Kontrolle.

> **Prüfe, ob die Allow-List auf allen Netzpfaden ankommt.** In den drei Portfolio-PRs, aus denen dieser Check stammt, sah das jedes Mal anders aus: ein selbstgebauter App-Builder, der nur bei konfiguriertem Auth oder CORS überhaupt genommen wurde (sonst servierte das SDK über `run()`); eine uvicorn-`--factory`, die **ohne Argumente** aufgerufen wird, sodass `--host` nur den Listener konfiguriert und die App nie erreicht; und ein deprecateter SSE-Pfad neben Streamable HTTP. Wer nur den Pfad verdrahtet, den er gerade vor Augen hat, schaltet den Schutz davon abhängig, welcher Zweig zufällig greift.
>
> Diese Klasse — dieselbe Kontrolle, mehrere Einstiegspunkte, einer vergessen — wird als eigener Check verallgemeinert. Hier genügt der Hinweis.

```diff
- app = mcp.streamable_http_app(host=host)
+ security = build_transport_security(host, port)
+ app = mcp.streamable_http_app(transport_security=security, host=host)
```
